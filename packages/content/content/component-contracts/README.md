# Component Contracts

Portable Markdown contracts help agents, designers, PMs, researchers, and developers use Design System outside the documentation site.

The JSON content remains the source of truth for rendered docs. A component contract should only summarize decisions that already exist in Design System content or specs:

- purpose and boundaries
- approved variants and states
- required foundations
- accessibility expectations
- responsive behavior
- MIEL decision rules
- rejection rules

Do not add a variant, prop, state, foundation, or behavior here unless it already exists in the Design System JSON or system specs.
